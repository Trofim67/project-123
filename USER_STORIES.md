# 👤 Пользовательские истории (User Stories)

*Шаблон: «Как преподаватель, я хочу ..., чтобы ...»*

1. **Добавление студентов**
   *   *Как преподаватель*, я хочу добавлять студентов с указанием фамилии, имени и группы, *чтобы* вести актуальный список своей группы.
   *   *Критерии приемки:* Пустые поля отклоняются; студент появляется в списке сразу после добавления; данные сохраняются.

2. **Удаление студентов**
   *   *Как преподаватель*, я хочу удалять студентов из списка, *чтобы* убирать отчисленных или ошибочно добавленных людей.
   *   *Критерии приемки:* Перед удалением появляется подтверждение; связанные отметки посещаемости также удаляются.

3. **Создание занятия**
   *   *Как преподаватель*, я хочу создавать занятие с указанием даты и дисциплины, *чтобы* группировать отметки по конкретным урокам.

4. **Отметка посещаемости**
   *   *Как преподаватель*, я хочу отмечать статус («Присутствовал», «Отсутствовал», «Опоздал») для каждого студента на занятии, *чтобы* фиксировать реальную картину.
   *   *Критерии приемки:* Можно изменить статус до сохранения; на одного студента и занятие только одна отметка.

5. **Просмотр статистики**
   *   *Как преподаватель*, я хочу видеть количество пропусков и опозданий по каждому студенту, *чтобы* оценивать дисциплину и успеваемость.
   *   *Критерии приемки:* Статистика обновляется автоматически; если данных нет, выводится сообщение об этом.

6. **Сохранение данных**
   *   *Как преподаватель*, я хочу, чтобы данные не пропадали после закрытия приложения, *чтобы* не вводить все заново каждый раз.
   *   *Критерии приемки:* Используется локальная база данных (Room); после перезапуска приложения все списки и отметки остаются на месте.
