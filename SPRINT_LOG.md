## 🟢 Спринт 1. Проектируем систему и создаем основу приложения
**Цель:** Определить требования, создать проект Android Studio и запустить стартовый экран.
*   **PO:** Описана проблема, составлено 6 User Stories, определены 4 экрана (Меню, Студенты, Отметка, Статистика).
*   **Lead Developer:** Создан проект `AttendanceControl` (Kotlin, Empty Views Activity). Сверстаны кнопки на главном экране (`activity_main.xml`), созданы заготовки Activity.
*   **QA / DevOps:** Создан Git-репозиторий, настроен `.gitignore`. Подготовлены первые 3 тест-кейса (запуск, главный экран, реакция кнопок).
*   **Результат:** Рабочий стартовый экран, структура проекта, коммиты всех участников. Спринт закрыт.

## 🟢 Спринт 2. Студенты и учебные группы
**Цель:** Реализовать добавление, просмотр и удаление студентов с проверкой ввода.
*   **PO:** Уточнены поля студента (Фамилия, Имя, Группа), подготовлены примеры ошибочного ввода.
*   **Lead Developer:** Создана модель `Student`, экран списка и форма добавления. Список отображается через `RecyclerView`. Реализовано удаление с подтверждением (`AlertDialog`).
*   **QA / DevOps:** Составлены тест-кейсы на пустые поля, пробелы, добавление/удаление. Проверена сборка.
*   **Результат:** Экран студентов работает, валидация обязательных полей работает. Спринт закрыт.

## 🟢 Спринт 3. Занятия и отметка посещаемости
**Цель:** Реализовать создание занятия и отметку статуса посещаемости.
*   **PO:** Согласованы статусы («Присутствовал», «Отсутствовал», «Опоздал»), сценарий выбора группы и даты.
*   **Lead Developer:** Создана модель `Attendance`. Экран отметки использует `RadioGroup` для каждого студента. Статусы сохраняются в текущем сеансе.
*   **QA / DevOps:** Тест-кейсы для всех статусов, пустого списка, изменения статуса.
*   **Результат:** Экран занятия функционирует, статусы различаются и изменяются. Спринт закрыт.

## 🟢 Спринт 4. Постоянное хранение данных
**Цель:** Подключить Room и обеспечить сохранение данных между запусками.
*   **PO:** Согласованы сущности `StudentEntity` и `AttendanceEntity`, описано поведение пустой базы.
*   **Lead Developer:** Подключен Room (Gradle). Созданы Entity, DAO и `AppDatabase`. Операции со списком студентов переведены с временных коллекций на базу данных (Coroutines).
*   **QA / DevOps:** Проверки чтения/записи, пустой базы, сохранения после перезапуска. Проверены версии Gradle.
*   **Результат:** Данные сохраняются после перезапуска приложения. Спринт закрыт.
